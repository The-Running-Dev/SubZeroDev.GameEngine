## Where this starts

PR #7 made `https://game-engine.subzerodev.com/` serve the README as a real route and put
the specs under `/docs/`. Verified live: the root returns 200 with zero `http-equiv="refresh"`
tags and renders `<h1>SubZeroDev.GameEngine</h1>`; `/docs/` and all seven spec pages return
200.

That settles *where* pages live. It leaves three questions about how they are **organised and
linked**, and two pieces of **upstream debt** that were noticed and deliberately not fixed at
the time.

## Constraints that shape every item below

- **URLs are now public and gated.** `onBrokenLinks` and `onBrokenMarkdownLinks` are
  `'throw'`, so a moved page fails the build rather than rotting quietly. Good — but it means
  any restructure has to keep `/docs/engine/<slug>` stable or change every reference in the
  same commit.
- **Numbering is positional.** `CLAUDE.md` is explicit: inserting a doc between existing ones
  means renumbering everything after it and rewriting every cross-link. Reordering is free —
  it is now a list in `docs/sidebar.ts` — but moving files is not.
- **The site root is generated.** `docs/src/pages/index.md` comes from `README.md` via
  `build/ConvertTo-DocumentationHomepage.ps1`, and the gate drift-checks it byte for byte.
  Any README edit means regenerating. There is no `pwsh` in the agent environment, so that
  regeneration is currently done by replicating the generator's logic and letting CI adjudicate.

## W-D1 — Sections in the docs

Group the specs into named sections instead of one flat `engine/` tree.

**Done in `sidebar.ts`, not by moving files.** The sidebar was
`[{type: 'autogenerated', dirName: '.'}]`, so sections would have come from folders — but
moving the specs would change every published URL, break every relative cross-reference, and
hit the positional-numbering trap above. A manual sidebar naming doc ids gives the same
sections at zero URL cost.

The grouping, which matches the reading order the docs already assert:

| Section | Contains |
|---|---|
| Orientation | `01-vision`, `02-architecture` |
| Contracts | `04-core`, `03-story-graph-kind` |
| Delivery | `MVP`, `TODO`, `OPEN-QUESTIONS` |
| Working on It | `guide/engine-package`, `guide/documentation-site` (added by W-D3) |

**Done:** every `/docs/engine/<slug>` URL is unchanged, and `sidebar_position` was removed from
all eight pages rather than left contradicting the explicit order. `04-core.md` said the
sidebar order came from `sidebar_position`; that sentence was corrected too.

## W-D2 — Deep-link to sections, and gate the anchors

Point README links at specific headings — `/docs/engine/core#the-kind-interface` rather than
`/docs/engine/core`.

**Close the gating hole first, or this adds unchecked links.** Anchors are validated by
neither checker today: `onBrokenLinks` covers routes, not fragments (that is `onBrokenAnchors`,
which defaults to `'warn'`), and `build/Test-Documentation.ps1` skips site-absolute targets
entirely (its line 391). Adding a dozen anchors without `onBrokenAnchors: 'throw'` recreates
exactly the hole PR #6 and PR #7 spent their time closing.

**Done:** `onBrokenAnchors: 'throw'` is set, and twelve README links now resolve to headings
rather than whole pages. Every anchor was computed with the gate's own slug algorithm and
checked against the real headings before pushing, since a wrong one now fails the build.

## W-D3 — All README links to the site

Five README links still point at `github.com`. Two of them should:
`SubZeroDev.GameOfLife` and `SubZeroDev.Platform` are other repositories.

The other three are the real work: `src/engine/` (twice) and `docs.ps1` are **code and tooling
with no page on the site to link to**. Making them site links means writing those pages first.

**Done, by writing the pages.** A *Working on It* section now holds
`guide/engine-package` (layout, commands, the determinism guard) and
`guide/documentation-site` (previewing, what is generated, the two link checks). Both are
contributor-facing rather than specifications, which is why they sit in their own section
instead of among the contracts.

They overlap `CLAUDE.md` and `agent.md` in places, deliberately and only in part: those two
are agent-facing and stay unpublished, and neither is a reasonable thing to hand a
contributor.

**Still open:** whether more of the tooling deserves published pages. Nothing else in the
README needed one.

## Upstream debt — `Docusaurus-Template`

Both of these belong upstream, not here. The precedent is set: the generator bug went up as
[#54](https://github.com/The-Running-Dev/Docusaurus-Template/pull/54) and its stale docs as
[#55](https://github.com/The-Running-Dev/Docusaurus-Template/pull/55), and only then was the
result adopted. Nothing in `build/` is locally modified — it is vendored verbatim, and keeping
it that way is what makes `Invoke-SetupDocs -Overwrite` safe to re-run.

### W-D4 — File the gate's link-parsing gap upstream

`build/Test-Documentation.ps1` extracts link targets with a capture group of `([^)\s]+)`, which
cannot match a target containing whitespace or `)` — `./some file.md`, `./foo(bar).md`. Such a
link is not reported broken; it is invisible to the gate entirely.

Raised by automated review on PR #6, verified against the source, and recorded in
`plans/02-w0-ci-workflow.md` as a known gap with the note that fixing it "deserves its own
review". It was never actually filed. **Confirmed not live in this repository** — no link
target here contains a space or `)` — so this is correctness work, not an outage.

### W-D5 — Sync the vendored gate

`build/Test-Documentation.ps1` was **33 lines behind** upstream's copy. Two fixes it lacked:

- **Anchor slug hyphenation.** Upstream replaces `\s+` with `\s`, so `## Phase 1 — Fixes`
  slugs as `#phase-1--fixes` the way GitHub does. Ours collapses the run and produces
  `#phase-1-fixes`, so a file whose anchors work on GitHub can fail this gate and vice versa.
- **Repository-root resolution**, with a working-directory fallback so the script also runs
  from outside the project.

**Sequence mattered:** the anchor fix changes what slugs the gate expects, and this repository
has em dashes in headings. It was synced *before* W-D2 added anchors, so a failure could only
have come from one of them. Every existing anchored link was checked against both the old and
new slug rules first — none changed meaning, so the sync landed clean.

Also worth reporting, though not ours to fix:
`docs/getting-started/installing-the-docs-system.md` upstream went stale with #52 — it still
tells non-`/` consumers to add `docs/src/pages/index.md` by hand and calls
`docs/docs/index.md` "Generated from `README.md`. Do not edit." Flagged in #54's body; another
session appeared to be working in that area, so it was left alone.
