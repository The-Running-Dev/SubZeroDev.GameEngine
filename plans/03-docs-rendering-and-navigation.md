# Docs Rendering and Navigation — Fixes and Conventions

**Status:** Applied. Verified by a production docs build.

**Scope:** Three defects found by actually rendering the spec site rather than reading the
markdown — a class of bug that is invisible in a diff. Fixed, with the conventions that
stop them recurring.

**Trigger:** PR #1's own test plan carried an unchecked box, *"Visual review of rendered
docs site (`./docs.ps1`)"*, and was merged without it. Everything below was found the
first time that box was actually ticked.

## Authority

- [`docs/docusaurus.config.ts`](../docs/docusaurus.config.ts) — `onBrokenLinks: 'throw'` at
  the time this plan was written; both Docusaurus checks are `'warn'` since PR #5.
- [`docs/sidebar.ts`](../docs/sidebar.ts) — one autogenerated tree over `docs/`.

## D1 — Metadata Lines Merged on Render

### Symptom

The Core page rendered its header as one run-on paragraph:

```text
Document status: Revision 1 — the platform core, as types Reading order: logically the
core underlies the kinds; numbered 04 only to avoid renumbering.
```

Two distinct metadata fields, presented as one sentence. Every spec doc had this.

### Cause

Markdown joins consecutive lines into a single paragraph. Adjacent `**Field:**` lines
separated by a single newline are one paragraph, not two — correct markdown, wrong intent.
The same rule merged the `> **Scope of this document**` label into its own body text in
five documents.

Affected: `01` (2 fields), `02` (2), `03` (3), `04` (2), plus the `Scope` blockquote in
`01`, `02`, `03`, `04`, `MVP`.

### Fix

A blank line between each metadata field, and a `>` spacer line after each `Scope` label.

**Not** two trailing spaces — the other markdown line-break idiom. Trailing whitespace is
flagged by `git diff --check`, which W0 requires in its local verification checklist
([`plans/02-w0-ci-workflow.md`](02-w0-ci-workflow.md)); that fix would fail branch
acceptance.

## D2 — The Sidebar Contradicted the Stated Reading Order

### Symptom

Nav order was Vision → Architecture → **Story-Graph Kind** → **Core Specification**, while
`04-core.md`'s own header instructs the reader to take it *"after `02-architecture`, before
or alongside `03-story-graph-kind`."* The navigation told a newcomer to do the opposite of
the instruction, on the two documents most prone to drift.

### Cause

`docs/sidebar.ts` autogenerates from the directory, and Docusaurus orders by filename. The
prefixes are positional (`CLAUDE.md`: *"Numbering is positional… Prefer appending"*), so
`03` sorts before `04` regardless of how they should be read. The `04` filename was itself
chosen to avoid a renumbering cascade — the ordering problem was inherited, not introduced.

### Fix

Explicit `sidebar_position` front matter, which decouples **navigation order** from
**filename order**. Files keep their numbers and every cross-link keeps working:

| Position | Document |
|---|---|
| 1 | `01-vision.md` |
| 2 | `02-architecture.md` |
| 3 | `04-core.md` |
| 4 | `03-story-graph-kind.md` |
| 5 | `MVP.md` |
| 6 | `TODO.md` |
| 7 | `OPEN-QUESTIONS.md` |

This is the cheap half of the positional-numbering problem: reordering the *reading
experience* no longer requires renaming files or rewriting links. Inserting a document
still does.

`sidebar_label` was added where the H1 wrapped to two lines in the nav ("Story-Graph Kind —
Content Model", "Open Questions & Known Concerns").

## D3 — Inconsistent Route Slugs

### Symptom

Numbered docs produced lowercase kebab routes (`/docs/engine/core`) because Docusaurus
strips the numeric prefix; unnumbered docs kept their filename case
(`/docs/engine/OPEN-QUESTIONS`). Two conventions in one sidebar.

### Fix

Explicit lowercase `slug` on the three unnumbered docs — `mvp`, `todo`, `open-questions`.
In-document links are file-based (`[MVP.md](MVP.md)`) and Docusaurus resolves them to
whatever the slug is, so no link needed rewriting — and the build proves it.

## Conventions Going Forward

1. **Order the sidebar with `sidebar_position`, never by renaming files.** Filenames are
   link targets; positions are presentation.
2. **A metadata field or a blockquote label needs a blank line after it.** A single newline
   merges it into the next line.
3. **Never use trailing double-spaces for a line break** — `git diff --check` rejects them.
4. **Render before merging a doc change.** A diff cannot show a merged paragraph, a
   mis-ordered sidebar, or a dead anchor. W0 automates this by installing the docs system,
   whose `docs-ci.yml` runs both a link-and-terminology gate and a production build
   ([`plans/02-w0-ci-workflow.md`](02-w0-ci-workflow.md)). **Until W0 lands**, the
   equivalent locally is the current hand-rolled pair:

   ```bash
   pwsh ./docs.ps1 -BuildOnly
   ```

   ```bash
   docker run --rm game-engine-docs sh -c "pnpm run build"
   ```

   After W0, use the installed tooling instead — `pwsh ./build/Test-Documentation.ps1` and
   `Invoke-DocsBuild`.

   `./docs.ps1` alone is **not** sufficient either way: it starts a dev server, and
   Docusaurus enforces broken links only during a production build.
