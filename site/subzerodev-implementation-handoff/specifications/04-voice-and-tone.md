# Voice and Tone Guide

## Voice summary

The voice is:

- intelligent
- technically credible
- understated
- dry
- self-aware
- slightly absurd
- never needy
- never corporate
- never impressed with itself

A useful shorthand:

> A Staff Engineer explaining an accidental architecture while Douglas Adams quietly edits the footnotes.

“Lucifer-style” in this context means charm, confidence, precision, and amused detachment. It does not mean theatrical devil imagery, gothic clichés, or constant references to hell.

## Humor target

Humor should occupy roughly 5–10% of the page.

The page must remain credible even if every joke is removed.

The jokes should make the serious statements more memorable, not replace them.

## Humor patterns

### Understatement

> That was unfortunate.

> Apparently that seemed reasonable.

> This escalated.

### Precise absurdity

> The engine does not know what a dragon is. Or a hotel. Or Bulgaria.

### Engineering contrast

> JavaScript frameworks reproduce faster than rabbits.

### Deadpan consequence

> Humans and AI submit the same commands. Equality is important. Especially when both are about to violate validation rules.

### Honest origin

> I still maintain this is entirely the LLM's fault. It should have given a shorter answer.

## Rules

### Do

- keep sentences short
- use pauses
- let whitespace carry timing
- make jokes from the truth
- use technical precision
- use callbacks
- allow the page to become more serious as it progresses
- write as someone who expects the reader to keep up

### Do not

- explain the joke
- use jokes in every section
- use memes
- use fake terminal hacker language
- overuse profanity on the public landing page
- imitate a stand-up routine
- make the engine sound unserious
- use “revolutionary,” “disruptive,” or “game-changing”
- call every architectural choice “insane” or “genius”
- add devil horns, flames, pentagrams, or obvious Lucifer imagery

## Tone progression

### Hero

Minimal, mysterious, confident.

### Origin story

Human, funny, narrative.

### Problem and insight

Dry but increasingly technical.

### Architecture

Clear and serious with one or two small jokes.

### Documentation CTA

Direct and practical.

### API/reference docs

Conventional technical language. Almost no humor.

## Approved recurring lines

- Build mechanics once. Create infinite games.
- Well... why not?
- That was unfortunate.
- Apparently that seemed reasonable.
- This escalated.
- The engine doesn't know what a dragon is.
- Games are data. Gameplay is code.
- Started as a joke. Escalated responsibly.
- No inventory systems were harmed during the making of this engine. Probably.
- Built because someone asked an LLM the wrong question.
- Built because nobody stopped asking better ones.

## Example rewrite

### Generic

> Our innovative engine enables developers to rapidly create games across multiple genres using reusable modular systems.

### Correct voice

> Build the mechanic once.
>
> Use it in more than one game.
>
> This should not be a controversial idea.
>
> Somehow, here we are.
